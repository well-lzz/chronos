# Harness 运行与恢复

本文说明 Super-agent 借鉴方案在当前工作区的核心实现。设计取舍见 [优化方案](design/harness-superagent-optimization.md)。远程 runner、模型诊断器及发现质量 A/B 评测仍属后续工作。

控制台身份校验、核心覆盖率门槛、真实模型验证入口与 Python 操作系统隔离见 [Harness 加固说明](harness-hardening.md)。

独立评估默认采用完整任务的 OS 沙箱子进程，主进程保留 Scope 授权、模型设置和鉴权控制台；范围切换会更换 PID 和状态目录。跨代历史及升级迁移、资源与网络边界、两小时验证状态见 [整任务隔离说明](harness-process-isolation.md)。下文的任务内 delegate 与恢复机制在每个隔离任务中继续使用。

## 配置

| 环境变量 | 默认值 | 行为 |
| --- | --- | --- |
| `CHRONOS_ASYNC_DELEGATE` | `false` | 为可委派的执行器增加 `delegate_start/status/cancel`；保留同步 `delegate`。 |
| `MAX_RUN_TOOL_STEPS` | `0` | 同一 run 的执行器共享工具步数上限；0 表示不限。子任务先预留，实际调用消耗，完成归还余量。 |
| `MODEL_CALL_TIMEOUT_SECONDS` | `180` | 每次模型请求的超时；超时按供应商故障退避，不计为调查停滞。 |

例如在已有任务配置上启用异步模式：

```bash
CHRONOS_ASYNC_DELEGATE=true MAX_RUN_TOOL_STEPS=1000 ./chronos --engagement /path/to/engagement.json --web
```

既有 Scope、工具审批、租约、委派深度/数量/步数和墙钟预算仍生效。Web 模式仍暂停启动，操作员保存授权范围并继续后才开始任务。

## 存储与恢复

- CLI 为状态目录持有内核级文件锁，防止两个当前版本的进程同时写入；目前支持 macOS 和 Linux。`writer.lock` 文件可保留，锁在进程退出时释放，不应通过删除文件解除活动锁。
- 会话读取失败、未知日志版本、关键提交失败或黑板写失败，会停止新模型请求与工具动作，并显示 `storage_error`。修复磁盘空间、权限或损坏记录后，重启恢复；不要删除整个状态目录来消除提示。
- JSON 快照通过私有临时文件、文件同步、替换及目录同步提交。会话和控制事件仅追加；仅丢弃末尾未完成记录，中间损坏会报错。
- 会话旁的 `*.control.jsonl` 保存版本化控制记录，包括执行意图、执行边界、结果指纹、模型请求指纹和进展影子指标。模型请求指纹包括消息及工具 schema 的 SHA-256，不代替完整正文记录；完整模型记录仍由 `LLM_RECORD` 控制。
- `subagents/<run>/budget.jsonl` 是运行级步数账本。并发分配先持久化，再派发，重启后恢复同一份余额。记录的是工具调用预算，token 仍沿用原计量机制。
- 存储或预算异常不会被主程序当作自然完成而清理运行身份。调度检查点提交失败会取消调度运行；重启先恢复持久化状态。

控制日志、会话、黑板和流量仍是不同文件。系统用稳定 ID 与恢复对账协调它们，不提供跨文件事务或外部网络副作用的 exactly-once 保证。

## 输入与异步子任务

Agent 会话输入框支持「添加文本」：选择 TXT、Markdown、JSON、日志、CSV/TSV、YAML、XML、INI/CONF 或 HTTP 文本后，可补充问题，也可仅发送文件。浏览器本地读取 UTF-8 或带 BOM 的 UTF-16，展示文件名并支持移除；点击发送后，文件名与正文组成同一条普通聊天消息，复用 `/api/command` 的 `chat`，不增加上传端点或独立文件存储。文件内容会进入现有持久化会话，并随会话发送给所选模型。附件是待分析的参考资料，不能扩大 Scope 或绕过工具审批。

每条最多 5 个文件，单个原文件及解码后的 UTF-8 文本均不超过 64 KiB，附件文本总量 96 KiB，消息序列化正文总量 128 KiB。空文件、非文本格式、无效编码、二进制控制字符及超限内容会明确报错，发送失败保留草稿和附件，不截取前 4,000 字节。新接收的文本附件在模型首次读取前不会被上下文压缩裁剪；仍受所选模型上下文窗口约束，窗口不足会报错，应分批发送或选用更大窗口。暂停任务接收消息后保持暂停，点击「继续」才由 Agent 处理。

`DeliverInput(eventID, source, text)` 是执行器的幂等输入入口；`source` 为 operator、runtime 或 child。相同 ID 在会话恢复和压缩后仍只排入一次。输入队列最多 128 条、512KiB，满时向调用方返回背压；已接受的输入不丢弃。普通控制台聊天仍产生新消息，调用方若需要传输级重试去重，应保留并复用事件 ID。

输入只在上一个工具调用及结果配对完成后的模型边界应用。应用表示进入持久化会话，不表示模型完成了工作。停止通过原有取消路径处理，避免排在普通输入之后。

异步工具：

- `delegate_start(task, max_steps, focus?)`：保存子任务元数据和预算后启动，立即返回 child ID。
- `delegate_status(agent_id)`：非阻塞读取直接子任务状态。
- `delegate_cancel(agent_id)`：请求取消；等待工具与浏览器清理后完成。
- `delegate_resume(agent_id, extra_steps, note?)`：以有界追加预算续跑未完成子任务；异步子任务沿原窗口继续。

子任务完成结果通过固定的 child ID 与 attempt ID 进入父任务 Inbox。父会话可以继续推理；没有其他工作时进入 `waiting_event`，由输入或完成事件唤醒。会话接力共享任务句柄和结果队列；Scope 更新也会收窄仍在旧 generation 中运行的子任务。

退出、任务取消和 Scope 切换等待子任务收尾，不把它们留作脱离任务的后台工作。`run_python` 仍为原来的有时限同步工具。

重启时：

1. 已完成的异步子任务从元数据和黑板引用恢复结果，不重新执行；重复补交由会话输入 ID 去重。
2. 原来仍在运行的子任务进入 `needs_reconciliation`，其预算余量释放。模型或操作员先检查证据与目标状态，再显式续跑并重新分配预算。
3. 存在待核对子任务时，父执行器不能自然完成；控制台显示待核对状态。新 Scope 不能接收旧 run 的事件。
4. 浏览器、认证状态及本机进程不能被当作已无损恢复。原工具结果缺失时补“结果未知”，不自动重发网络动作。

同步 `delegate` 继续兼容原有模式；其跨进程子句柄恢复没有在本轮扩展。异步任务持久化需要保留整个运行目录。

## 读取证据与观测

控制台「工具行为」统计当前选中执行器在本 run 内累计发起的工具调用，并按工具名称汇总。普通事件、带调用 ID 的结构化事件及子任务事件共用记账入口；子任务调用归属各自的活动流，不重复算入父执行器。工具结果不重复计数，统计不受最近 300 条实时事件窗口限制，重启后从活动日志恢复。执行器启动时按各工具累计值取大合并旧检查点，避免旧值覆盖日志或两份记录相加导致重复计数。被拒绝、取消或未执行的已发起调用仍会计入，次数不代表执行成功；在活动区选择「工具」可核对参数与结果。

`artifact_get` 提供当前 run 内的 Fact、Finding、Subgoal、Challenge、Verification、Digest 读取：

```json
{"kind":"finding","id":"v3","neighbors":true,"offset":0,"length":8192}
```

不填 `id` 时返回按类型和 query 筛选的确定性索引，每页 20 条。正文每次最多 8192 字节，邻居 ID 最多 20 个；不会因为读取缺失记录而访问目标，也不接受其他 run 的路径。它返回当前修订，不提供任意历史版本回溯。流量继续使用 `traffic_get/search`。

运行快照中的 `health` 展示排队输入、活动工具、模型请求开始时间、运行中子任务和待交付结果。进展影子指标按去重事实/发现、证据接地、验证、反驳和子目标解决分别记录，避免把大量重复 Fact 误认为质量提升；本轮不据此自动改变终止策略，也没有增加模型裁判。

Webhook 先持久化到 Outbox，失败按 5—300 秒退避，运行中及后续启动时补交。每次发送带相同 `Idempotency-Key`；服务端成功后、本地回执提交前崩溃仍可能重发，接收端应使用该键去重。改变端点不会把旧端点的待发送内容转发给新端点。

## 部署与回退

[systemd 示例](../examples/chronos.service) 用于 Linux 上的进程监督，需先安装二进制、运行用户、Node/浏览器依赖及授权任务配置。它是示例文件，本轮没有安装或启动系统服务。进程级监督与任务内的超时、状态恢复分别处理不同故障。

异步模式默认关闭，可先对新任务启用。已有异步子任务记录的 run 必须继续使用相同开关恢复；关闭开关不会静默遗弃其子任务，需改回开关或创建新 run。当前程序拒绝它不支持的状态版本；**历史旧二进制不认识新增协议，不能指望它拒绝或正确解释新目录**。回退应使用升级前备份或新目录，不用旧程序接管本轮写入的活动状态。

本轮未实施云端/本地 daemon、跨设备权限代理、Python 后台作业、LLM Watchdog 或自动资产复测。它们依赖单独的环境隔离与评测，不影响当前单机核心闭环。
